# Why this, not that: every choice compared honestly

Verdicts: WINS = measurably better; TIE = numbers close, chosen for a stated reason; LOSES = tested and lost, not relied on; TRADE-OFF = worse on accuracy, chosen on purpose for access or privacy; MIXED = better on some measures, worse on others; NOT MEASURED = reasoned choice only.

Generated by `python demo/run_demo.py` from commit 76d8e6a99b412c2fd712d4aa8a265f979baee691-dirty. Simulated / preliminary, public and synthetic data, not real deployment data.

## Personal baseline vs one fixed range for everyone

**We use:** Personal baseline  
**Verdict:** MIXED

| Measure | Fixed range 21 to 35 days | Our personal baseline (hybrid) |
|---|---|---|
| PCOS-like caught | 100% | 99% |
| Anemia-like caught | 99% | 92% |
| Thyroid-like caught | 85% | 99% |
| False alarms per 100 normal cycles | 3.36 | 4.27 |
| Healthy people ever flagged | 33% | 28% |

**In plain words:** A fixed range judges everyone against the average woman. A woman whose normal cycle is 37 days gets flagged every single month, even though nothing is wrong for her (our tests check exactly this case). The personal baseline learns her own normal. Measured: it catches more thyroid-like changes (99% vs 85%) and flags fewer healthy people, but on this simulator the fixed range raises slightly fewer false alarms per cycle (3.36 vs 4.27).

**Where we could be wrong:** Most simulated women have normal cycles well inside 21 to 35 days, which flatters the fixed range. The advantage of a personal baseline should be larger for women whose normal sits near the edges; we have not measured that subgroup separately yet.

## Which change detector for Tier 1

**We use:** Hybrid (z-score + CUSUM + rules)  
**Verdict:** TIE

| Detector | PCOS / anemia / thyroid caught | False alarms per 100 | Healthy ever flagged |
|---|---|---|---|
| z-score only | 94% / 36% / 65% | 2.91 | 35% |
| EWMA chart only | 100% / 88% / 100% | 2.92 | 20% |
| CUSUM only | 100% / 94% / 100% | 4.39 | 13% |
| Isolation Forest | 95% / 79% / 89% | 1.79 | 45% |
| Our hybrid | 99% / 92% / 99% | 4.27 | 28% |

**In plain words:** A z-score alone reacts to sudden jumps but misses slow creeps (it caught only 36% of anemia-like changes). CUSUM catches slow creeps but reacts later. The hybrid combines both and catches PCOS-like changes in the same cycle they start. But the EWMA chart alone does about as well with fewer false alarms (2.92 vs 4.27) and flags fewer healthy people (20% vs 28%).

**Where we could be wrong:** On these numbers the EWMA chart is a credible replacement for the hybrid. We are reporting that, and it is an open decision for the team.

## Neural network (GRU) vs simple statistics for spotting change

**We use:** Simple statistics (Tier 1); GRU kept as Tier 2 under evaluation  
**Verdict:** LOSES

| Method | PCOS / anemia / thyroid caught |
|---|---|
| Tier 1 statistics | 99% / 92% / 99% |
| Exponential smoothing | 90% / 63% / 30% |
| GRU | 85% / 48% / 27% |
| LSTM | 84% / 46% / 29% |
| 1D CNN | 85% / 47% / 32% |

**In plain words:** Neural networks need lots of examples per person. Each simulated person has only 16 to 30 cycles, so simple statistics that track one person's average beat all three neural networks. GRU, LSTM and CNN were almost identical to each other.

**Where we could be wrong:** With much longer histories, or real data with richer patterns, a neural network could catch up. The GRU is kept, exported and tested, but it does not raise flags.

## Symptoms only vs using lab tests

**We use:** Symptoms only  
**Verdict:** TRADE-OFF

| Inputs | Best AUC |
|---|---|
| Symptoms only | 0.891 |
| Symptoms + vitals | 0.894 |
| With labs + ultrasound (reference) | 0.959 |

**In plain words:** Lab tests make the model better (AUC 0.96 vs 0.89), but anyone who already has those tests has seen a doctor. The point of MyCycle is to nudge people before that step, at home, for free. We accept the lower accuracy and state it.

**Where we could be wrong:** Symptom-only screening will miss some cases; that is why every flag says consider consulting a doctor, and a quiet result is not an all-clear.

## Where the learning happens

**We use:** Federated learning  
**Verdict:** WINS

| Setting | Raw data leaves phone? | AUC |
|---|---|---|
| All data pooled on a server | Yes | 0.892 |
| Each phone alone | No | 0.740 |
| Federated learning (FedAvg) | No | 0.878 |

**In plain words:** Pooling everyone's data gives the best accuracy but puts intimate data on a server. Keeping it on each phone alone is private but weak (AUC 0.74). Federated learning keeps data on the phone and gets 0.88, close to pooling.

**Where we could be wrong:** Measured with 8 simulated phones on the PCOS dataset, not real phones; real networks add dropouts and delays.

## Which federated method

**We use:** FedAvg  
**Verdict:** TIE

| Method | AUC | Accuracy |
|---|---|---|
| FedAvg | 0.878 | 83% |
| FedProx | 0.894 | 68% |
| FedPer (personal head) | 0.635 | 54% |

**In plain words:** FedProx ranked slightly better (AUC 0.89 vs 0.88) but got far fewer answers right at the default cut-off (68% vs 83%). FedPer was weakest. FedAvg is the simplest, most standard method and the best balance here.

**Where we could be wrong:** One run per setting on a small dataset; FedProx's AUC edge could be real. SCAFFOLD and FedAdam were not run.

## Adding differential privacy

**We use:** FedAvg with differential privacy  
**Verdict:** TRADE-OFF

| Setting | Epsilon | AUC | Accuracy |
|---|---|---|---|
| No privacy noise | none | 0.878 | 83% |
| Noise 0.5 | 23.92 | 0.846 | 67% |
| Noise 1.0 | 4.27 | 0.842 | 67% |
| Noise 1.5 | 2.04 | 0.880 | 69% |
| Noise 2.0 | 1.36 | 0.860 | 67% |
| Noise 3.0 | 0.81 | 0.859 | 67% |

**In plain words:** Without noise, a clever server could learn things about one person from her update. Differential privacy adds noise so that any one person barely changes the result, with a measured budget, epsilon. It costs accuracy, and we show exactly how much.

**Where we could be wrong:** Secure aggregation and homomorphic encryption are other ways to hide updates; we did not test them. DP gives a bounded leak, never zero.

## Personalizing the neural network per user

**We use:** Not used (statistical baseline is already personal)  
**Verdict:** LOSES

| Measure | Before fine-tuning | After fine-tuning |
|---|---|---|
| PCOS-like caught | 67% | 83% |
| Thyroid-like caught | 11% | 67% |
| False alarms per 100 normal cycles | 0.85 | 18.64 |

**In plain words:** Tuning the model on a user's first 4 cycles made it catch more changes, but it also started crying wolf far more often. Too many false alarms make people ignore flags, so we do not use it.

**Where we could be wrong:** With more cycles for fine-tuning, or a false-alarm penalty during tuning, this could improve.

## Indian survey (NFHS-5) vs US survey (NHANES) for anemia and thyroid

**We use:** NFHS-5  
**Verdict:** NOT MEASURED

| Reason | NFHS-5 |
|---|---|
| Population | Indian women aged 15 to 49, our users |
| Size | 126,625 non-pregnant women |
| Anemia label | Real measured haemoglobin |
| Licence | Public domain (CC0) |

**In plain words:** Our users are Indian women. A US survey would describe a different population, diet and anemia rate. NFHS-5 is India's own survey with real blood measurements.

**Where we could be wrong:** We did not run NHANES, so this is a reasoned choice, not a measured comparison.
